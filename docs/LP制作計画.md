## 2. デザインコンセプト

**渋谷で見つける、黄色いチキンスタンド。**

黄色い広告写真で食欲を引き、白いメニュー紙面で料理を選び、最後に地下1階の店舗へ迷わず向かえるLPにする。海外のファストフード広告のような大胆な商品スケールと、旅行中にも読みやすい情報整理を組み合わせる。

この店舗固有の設計の起点は、チキンバーガー2種類、セット・ラップ・ヤンニョムという5枚の実素材、ハラール対応、渋谷駅から徒歩約7分、地下1階という来店条件。

### ビジュアルのルール

- ヒーローは中央の商品を主役にした一枚のポスター構成。写真を画面全体の背景として扱い、短いコピーを上部に重ねる。
- 白い商品写真の背景を白いページになじませる。元画像は不透明なので、透過画像のように黄色地に直接重ねない。
- 商品説明は写真の比率・料理の形・情報量に合わせて配置。バーガーの比較、横長のセット、斜めのラップ、チキンの塊でリズムを作る。
- 白い余白、濃い文字、黄色い面、細い罫線を基本要素にする。角丸カードや影付きボックスの繰り返しを主構造にしない。
- 認証・所在地・営業時間は、料理の広告表現と分けて読みやすい活字で示す。
- 実在ロゴが未提供のため、初期案は正式店名の文字組み。公式ロゴや認証マークを新たに作り込まない。

## 4. ページの構成と画面設計

### 01 — ヘッダー

白地、またはヒーローに連続する黄色地の細いヘッダー。店名は正式な英字名称を2〜3行に組む。PCはMenu / Halal / Access / Instagramと日本語・Englishの切替を配置する。

スマートフォンは店名、言語切替、メニューボタン。展開メニューの中に各セクションへのリンクとInstagramをまとめる。開閉ボタンに状態を伝えるラベルを持たせ、閉じた後はボタンへフォーカスを戻す。

### 02 — ヒーロー：黄色いフードポスター

**短いコピー案：CRISPY. JUICY.**

小さな補足：HALAL CHICKEN IN SHIBUYA

日本語ページの補足候補：渋谷で、サクッとハラールチキン。

コピー、補足1行、2つの導線に絞る。長い店舗説明、価格一覧、営業時間一覧は後続に置く。上記の補足は日本語版・英語版で入れ替え、同じ画面に全候補を併記しない。

PCの構図：

```text
┌────────────────────────────────────────┐
│ 正式店名         Menu  Halal  Access  JP/EN │
│                                        │
│              CRISPY. JUICY.            │
│        HALAL CHICKEN IN SHIBUYA         │
│                                        │
│           大きなチキンバーガー           │
│           黄色い背景と自然な影           │
│                                        │
│       [メニューを見る] [Googleマップ]     │
└────────────────────────────────────────┘
```

画像自体に文字やボタンを焼き込まず、HTMLで表示する。商品と文字が重ならないよう、写真の黄色い余白とページ背景を連続させる。

PCは横長、スマートフォンは生成済みの縦長画像を使い分ける。ヒーローの基準高は`100svh`からヘッダーとモバイル固定導線の高さを差し引く。横向き端末や文字拡大で窮屈な場合は自然に高さを延ばし、1画面に収めるために文字や商品を切らない。

### 03 — メニュー：2つのバーガーを選ぶ

白地の大きな見出し「MEET YOUR CHICKEN.」の下に、マスターチキンバーガーとてりやきチキンバーガーを並べる。商品写真は同じ見え方の大きさに調整し、細い罫線で区切った比較しやすい紙面にする。

商品名は日本語版では日本語を主、英字を補助にする。説明は各1〜2文。スマートフォンは1商品ずつ縦に配置し、画像を横幅いっぱいに見せる。主要情報をスライド操作の奥に隠さない。

### 04 — セットとサイド：料理の形に合わせたメニュー展開

前セクションと同じメニュー紙面の中で、セット写真をPCの横幅全体に使った大きな段として配置。紙コップを含めた元写真全体を見せ、写真にない選択肢やセット内容は追加しない。

その下にアジアンツイスターとヤンニョムチキンを配置する。PCはラップをやや縦長に見せる広めの領域、チキンを低めの領域として高さに変化をつける。ただし元画像の550×440pxを超えて過度に引き伸ばさず、余白と文字の大きさで見せ場を作る。商品全体が分かる`contain`を基本にする。

スマートフォンは、バーガー2種→セット→ツイスター→ヤンニョムの順で縦読み。横スクロールを必須にしない。セットの「お得」「割引率」は、比較価格が確定するまで掲載しない。

### 05 — ハラールの案内：選ぶための事実を伝える

薄い罫線で分けた白い横長の情報セクション。見出し案「HALAL, HERE IN SHIBUYA.」。ハラール認証を受けたチキン専門店であることを、提供情報に基づいた短文で説明する。

認証機関・認証書・正式マークは未提供。入手できた場合に事実と許可範囲に沿って掲載する。「すべての方に安全」「アレルギー対応」「専用調理設備」「礼拝室」「アルコール不使用」など、提供されていない条件は追記しない。

ここに「来店注文」「テイクアウト」の利用案内を2つの短い行で配置する。デリバリーはサービス名・稼働・店舗への直接リンクが確認できた段階で追加できる設計とする。

### 06 — アクセス：渋谷駅から、地下1階へ

黄色い大きな面に「SEE YOU IN SHIBUYA.」。駅からの徒歩時間に続いて、**J+RサイドJビル 地下1階 / B1F**を大きく表示する。店舗を見つけるための情報をここに集中させる。

住所は日本語・英語の各ページで読める表記を用意。営業時間、定休日、座席、お支払い、駐車場を見出し付きの行で整理する。

大きな「Googleマップで開く」を住所直下に置き、提供された検索URLへリンクする。駅出口番号、曲がる場所、入口の外観は未確認なので案内図に創作しない。店舗外観・階段の写真を後で入手できれば、アクセス欄に追加する価値が高い。

地図埋め込みは必須にせず、初期案は軽量なリンク中心。電話番号は確認できるまで表示・発信リンクを保留する。

### 07 — フッターとInstagram

白地に正式店名を大きく組み、Instagram、Googleマップ、言語切替、コピーライトを配置する。Instagramは「最新情報を見る」と目的を伝える。未取得の投稿画像や架空のSNSレビューは作らない。

## 6. 日英対応

- 日本語は`/`、英語は`/en/`の2ページを同じコンポーネントから出力する。
- 英字見出しを添えるだけでなく、料理説明、住所、営業情報、操作ラベル、画像の代替テキストまで切り替える。
- 商品情報は1つのデータに集約し、`name.ja` / `name.en`等で管理する。営業時間・URL・価格確認状態の二重管理を避ける。
- 切替表示は「日本語 / English」。現在言語を明示し、言語と国を同一視する国旗アイコンは使用しない。
- 対応するセクションのアンカーを言語切替先にも付け、メニュー閲覧中なら英語版のメニューへ移動できるようにする。
- 日本語版と英語版のページタイトル・description・`lang`・`hreflang`を用意。公開URLが確定してからcanonicalを設定する。
- 英語の案：`Menu`、`Directions`、`Takeaway available`、`Approx. 7 min walk from Shibuya Station`、`B1F`。

Astroのロケール別ディレクトリと共通部品の方針は、[Astro公式の国際化ガイド](https://docs.astro.build/en/guides/internationalization/)に沿って具体化する。

## 7. GSAP・Lenisによるアニメーション計画

動きの目的は、料理の登場、メニューへの誘導、情報のまとまりを伝えること。価格やアクセスに到達するまで待たせない。

| 対象 | PC | スマートフォン | 目安 |
| --- | --- | --- | --- |
| ヒーロー | 写真は即表示。見出しを小さく上へ移動させて表示 | 小さな移動とフェード | 0.5〜0.7秒、移動12〜20px |
| ヒーローからメニュー | 写真をスクロールに合わせ最大3%程度拡大 | スクロール連動拡大を省略 | スクロール範囲内のみ |
| メニュー | 商品写真・商品名をグループ単位で表示 | 各商品を1回だけ穏やかに表示 | 0.4〜0.6秒、時差0.08秒程度 |
| リンク | 下線の伸び、矢印の短い移動 | 押下時の色変化 | 0.15〜0.25秒 |
| アクセス | B1Fと住所を同時に自然に表示 | 同様、移動量は小さく | 0.4秒程度 |

- GSAP + ScrollTriggerで表示・スクロール連動を管理する。レスポンシブ条件は`gsap.matchMedia()`を使用する。
- LenisはPCのマウス／トラックパッド操作で適用し、軽い慣性に調整する。スマートフォンとタッチ主体のタブレットは標準スクロールを基本とする。
- Lenisのスクロール更新をScrollTriggerへ連携し、GSAPのtickerを1つの更新ループとして使用する。二重のrequestAnimationFrameループを作らない。[Lenis公式の連携例](https://github.com/darkroomengineering/lenis#gsap-scrolltrigger)を基準にする。
- `prefers-reduced-motion: reduce`ではLenisとスクロール連動演出を停止し、必要情報を静止状態で表示する。
- 初期CSSでは内容を読める状態にする。JavaScriptの失敗時も写真・説明・リンクを利用できるようにする。
- 固定ヘッダーの高さに合わせてアンカー位置を補正する。アニメーションや言語切替でフォーカスを見失わないようにする。
- 長いピン留め、強制横スクロール、スクロールを妨げる全画面演出、自動で動き続ける料理、待機用ローダーは設けない。

[GSAP公式のScrollTriggerガイド](https://gsap.com/docs/v3/Plugins/ScrollTrigger/)を参照し、実装時はインストール済みバージョンとAPIを照合する。

src/
  pages/index.astro             日本語
  pages/en/index.astro          英語
  layouts/SiteLayout.astro      共通メタ・言語設定

    SiteHeader.astro

SEOは日英タイトル・description・OG画像・Restaurantの構造化データを用意する。電話・価格・SNSレビューの集計値など未確認の情報を構造化データにも入れない。公開URLが未定のためcanonical・sitemap・robotsの本番URLは実装時に確定させる。

## 11. 制作順序と完了条件

1. 本計画と生成素材を基に、PC・モバイルの画面を組む。
2. 5枚の商品写真を配置し、写真のサイズ・余白・商品名の読みやすさを調整する。
3. 日英の文章・店舗情報・言語切替・固定導線を実装する。
4. GSAP・Lenisを加え、端末別の動作と動きを減らす設定を仕上げる。
5. 公開前の事実確認を反映し、画像・メタデータを最適化する。
6. ビルド、PCとモバイルの表示・操作を確認する。

実装後は360 / 390 / 768 / 1024 / 1440pxを基準に、商品写真の切れ・横はみ出し・固定ボタンの重なり・日英切替・アンカー位置・GoogleマップとInstagramのリンク・キーボード操作・reduced-motionを確認する。

ヒーロー画像は読み込み優先度と容量を測り、初期表示を遅らせないように調整する。約550px幅の商品写真は高解像度ディスプレイで鮮明さに限界があるため、より高画質な原本が後で用意できれば同じ配置で差し替える。

開発サーバーを起動する場合は、このプロジェクトのAGENTS.mdに従って`astro dev --background`を使用し、`astro dev status` / `astro dev logs` / `astro dev stop`で管理する。
